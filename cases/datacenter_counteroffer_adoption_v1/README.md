# Data-center counteroffer adoption

This diagnostic family isolates whether a developer model can adopt a complete
written counteroffer and preserve that exact package through signature. The
cases are nested prefixes of the same bounded data-center project:
land only, land plus power, and land plus power plus EPC.

V1 exposed an initial-offer confound: a model could fail before receiving any
counteroffer because it had to invent a valid opening package. V2 preserves the
same terms and depth ladder but publishes a valid nonexact starter package in
each first-offer observation. It also treats an explanatory walk as a valid
intentional walk instead of a malformed action. V1 remains frozen as preflight
evidence; V2 is the adoption-focused instrument.

V3 makes one further schema-alignment repair discovered by the V2 probe: null
offer prose is normalized to a neutral nonbinding message. Structured terms are
never changed. The scorer and counteroffer policy are unchanged.

All cases pin the same objective-aware V2 source case by content hash. The
ladder therefore measures increasing negotiation depth, not performance across
independent projects. Partial-prefix outcomes have no certified project cashflow
meaning and are never scored as economic optima.

The primary estimand is the fraction of required agreements for which the
developer received a controlled written counteroffer, copied its complete
structured terms exactly, and signed the accepted offer ID. Provider failures
are exclusions; malformed or otherwise invalid model actions are included with
zero task credit.
